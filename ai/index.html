제휴 마케팅 캠페인과 파트너 협업·성과를 관리하는 팀 웹 서비스입니다. 캠페인 CRUD API 5개와 평가 서비스 분리·Kafka 통신을 맡았으며, 평가 알고리즘 자체는 구현 범위가 아닙니다.

담당 업무 및 문제 해결

문제

평가 서비스가 캠페인 관리 데이터베이스를 직접 조회하지 않고도 필요한 정보를 받아야 했고, 평가가 끝난 뒤 결과를 원래 서비스로 돌려주는 흐름이 필요했습니다.

구현

캠페인 생성·목록·상세·수정·삭제 API 5개를 구현하고 평가 기능을 별도 서비스로 분리했습니다. 캠페인·혜택·목표 데이터를 DTO로 정리한 뒤 양쪽 서비스의 Kafka Producer·Consumer를 연결했습니다.

검증

각 API 요청의 응답을 확인하고, 평가 요청 시 캠페인 정보가 Kafka 메시지로 전달된 뒤 평가 결과가 원래 서비스로 돌아오는 과정까지 확인했습니다.

배운 점·개선

서비스를 나누는 것보다 요청 데이터의 경계와 응답 흐름을 먼저 합의하는 일이 연동 안정성에 중요했습니다. 다음에는 메시지 스키마와 실패·재처리 시나리오를 문서화하고 통합 테스트로 남기겠습니다.

담당 업무 및 문제 해결

문제

병원을 찾은 사용자가 관심 병원을 저장해 다시 확인하고 위치를 지도에서 바로 볼 수 있어야 했습니다. 주소 목록만으로는 위치를 한눈에 파악하기 어려웠습니다.

구현

북마크 등록·상세·목록·삭제 기능을 구현했습니다. 병원의 Kakao 장소 식별자·주소·위도·경도를 연결하고, 프론트엔드에서 Kakao Map API를 호출해 위치를 마커로 표시했습니다.

검증

북마크 CRUD와 병원 좌표의 지도 마커 표시가 전체 서비스에서 함께 동작하는지 확인했습니다. 별도 사용성 평가는 진행하지 않았습니다.

배운 점·개선

지도 API 호출 자체보다 병원 데이터·북마크·화면 상태를 하나의 사용자 흐름으로 연결하는 일이 중요했습니다. 다음에는 사용자 테스트로 저장 후 재탐색 흐름의 사용성을 확인하겠습니다.

03ROAD | 카메라 영상으로 차선을 찾아 가상 차량의 조향값 계산

2023.07–2023.09 · 3인 팀

노트북 가상 주행 환경에서 카메라 영상으로 차선을 인식해 트랙을 주행한 3인 동아리 프로젝트입니다. 실제 차량·센서는 사용하지 않았으며, 허프 변환 적용과 조향값 계산 코드 일부를 맡았습니다.

본인 수행 범위
학습·회의 조율 · 허프 변환 학습·적용 · 조향값 계산 일부
사용 기술
Ubuntu 20.04 · ROS · Python · OpenCV

담당 업무 및 문제 해결

문제

처음 사용하는 Ubuntu·ROS·OpenCV 환경에서 차선 검출 결과를 가상 차량의 조향 명령으로 연결해야 했습니다. 조향값이 너무 크면 차량이 급하게 방향을 틀며 트랙을 벗어났습니다.

구현

실행 순서와 이미지 처리 과정을 단계별로 확인한 뒤 허프 변환을 적용했습니다. 좌우 차선 중앙과 화면 중심의 차이를 조향값으로 바꾸는 코드 일부를 작성하고, 주행 결과를 보며 계수를 조정했습니다.

검증

조향 계수를 낮춰 트랙 이탈을 줄였고 팀의 가상 트랙 주행 완성에 기여했습니다. 별도 평가 도구로 인식률을 측정하지는 않았습니다.

배운 점·개선

값을 바꿔가며 주행만 확인해 로그와 정량 기준을 남기지 못한 점이 한계였습니다. 다음에는 입력 영상·조향 계수·이탈 여부를 함께 기록해 변경 전후를 비교하겠습니다.
